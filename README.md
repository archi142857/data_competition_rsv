# 일본 RSV 유행의 지역별 관계와 4주 후 보고 수 예측

제1회 과학데이터혁신 경진대회(서울대 과학데이터혁신연구소)에 참가하면서 일본 RSV 전파 데이터를 분석한 코드다.

한 현의 RSV 보고 수를 4주 앞서 예측할 때, 가까운 현 세 곳의 최근 보고 수를 같이 넣으면 예측이 나아지는지 확인했다. 일본 전체가 같은 계절 주기를 따라서 생긴 효과일 수도 있어서 전국 합계를 넣은 모델과도 비교했다.

## 결과

중간보고서까지 (고정 설계, 스크립트 01~06)

- 인근 3현 정보를 넣으면 2021년, 2022년, 2023년 모두 로그 MAE가 줄었다. 세 해를 합치면 0.818에서 0.739가 됐다.
- 전국 합계를 이미 넣은 모델에 인근 정보를 더해도 2021년과 2023년에는 오차가 더 줄었다.
- 2022년에는 오사카, 아이치, 효고에서 7월 정점 직후 예측이 실제보다 크게 나와서 원래 단위의 RMSE가 81.0에서 93.6으로 커졌다.

최종보고서에서 더한 것 (스크립트 07~13)

- 2022년 세 현의 과대 예측은 인근 정보를 넣기 전부터 있었고, 인근 3현의 4주 변화 입력이 이를 더 키웠다. 인근 현이 먼저 정점에 이른 현에서는 인근 정보가 정점 전후의 오차를 줄였고, 자기 현이 먼저 정점에 이른 현에서는 키웠다(사후 진단).
- 인근 3현을 무작위 3현으로 바꾸면 전국 합계 모델에 더했을 때의 개선이 0.025에서 0.003으로 줄었다. 이득은 가까운 현일수록 컸다.
- 세 해 전체의 결론은 인근 현의 수나 고르는 방식을 바꿔도, 보고가 2주 늦어도, 그래디언트 부스팅으로 바꿔도, 오키나와나 2020년 자료를 빼도 같았다.
- 기준으로 삼은 M1은 현재값을 그대로 쓰는 M0와 비슷한 정도로 약했다. 계절 입력을 빼서 기준을 강화하면 인근 정보의 이득(M2와 M1의 로그 MAE 차이)은 0.079에서 0.049로 줄었고, 최근 26주 평균 입력을 넣었을 때는 0.059, 부스팅에서는 0.057이었다. 줄어도 신뢰구간은 0보다 아래였다.
- 2022년의 개선은 작았고 예측 시점 보고 수가 5건 미만인 행에서 나왔다. 주 단위로 묶어 다시 뽑은 구간은 0을 포함한다.
- 유행의 무게중심 예측은 0.6주쯤 나아졌다. 유행 시작 주의 오차는 어느 모델이나 4주 안팎이었고, 인근 정보가 시작 주 예측을 개선했는지는 기준에 따라 달라서 뚜렷하지 않았다.
- 그래디언트 부스팅의 수치는 입력 끝자리의 작은 차이에도 소수 셋째 자리가 달라졌다. 보고서에는 잡음을 더한 10번 반복에서 방향이 바뀌지 않은 결과만 적었다.
- SIRS 가상 자료 실험은 가정(외부 유입, 전파율 감소 폭)에 따라 결과가 바뀌어서 보고서 본문의 근거로 쓰지 않고 부록 B에 적었다.

이 결과는 인근 현의 보고가 예측에 쓸모 있다는 것까지다. 현 사이의 전파 경로를 밝힌 것은 아니다.

노트북과 `code/` 안의 스크립트는 같은 분석이다. 처음부터 끝까지 한 번에 보려면 노트북을, 특정 분석만 다시 돌려 보려면 스크립트를 쓰면 된다. 01~06은 중간보고서에서 고정한 설계이고 계산은 그때와 같다. 07부터는 그 설계에서 한 가지씩만 바꿔서 다시 계산한다. 관측을 빼거나 예측 기간을 바꾸는 분석은 평가 행이 달라진다.

## 실행 방법

**1. 자료 넣기**

대회에서 받은 `RSV_transmission_in_Japan` 폴더(`cases.csv`, `population.csv`, `humidity.csv`, `temperature.csv`)를 저장소 맨 위에 그대로 넣는다. 대회 제공 자료라서 저장소에는 올리지 않았고, `.gitignore`에 넣어 둬서 실수로 커밋되지도 않는다.

```
data_competition_rsv/
├── RSV_transmission_in_Japan/
│   ├── cases.csv
│   └── ...
├── code/
└── ...
```

**2. 패키지 설치**

```
pip install -r requirements.txt
```

Python 3.13, numpy 2.5.3, pandas 3.0.5, scikit-learn 1.9.1, scipy 1.18.1, matplotlib 3.11.2에서 돌려 봤다. 릿지 회귀의 결과는 환경이 달라도 같게 나오지만, 그래디언트 부스팅(`10`)은 버전이나 계산 순서가 달라지면 소수 셋째 자리가 달라질 수 있다.

**3. 실행**

노트북은 `RSV_final_analysis.ipynb`를 열고 위에서부터 실행하면 된다. 전체가 7분쯤 걸린다.

스크립트는 저장소 폴더에서 아래처럼 돌린다. 파일마다 필요한 계산을 처음부터 다시 하기 때문에 순서와 상관없이 하나만 돌려도 된다.

```
python code/01_data_check.py
python code/04_forecast_eval.py
python code/08_neighbor_def.py
```

대부분 몇 초면 끝난다. 오래 걸리는 것은 `07`(20초), `08`(무작위 200번, 1분), `10`(잡음 확인 10번 포함, 1분 20초), `12`(15초), `13`(모의실험 200번, 4분)이다.

그림은 `figures/`에, 표는 `results/`에 저장된다. `results/facts_*.csv`는 보고서 본문에 쓰는 낱개 숫자를 모아 둔 파일이다.

## 분석 설정

- 예측 대상: 각 현의 4주 뒤 주간 보고 수
- 평가: 2021년, 2022년, 2023년을 한 해씩 따로 평가. 학습에는 평가 연도 1주 전까지 결과가 확인된 자료만 씀
- 모델: M0 현재값 유지, M1 자기 현 이력, M2 인근 3현 추가, M3 전국 추가, M4 인근과 전국 추가 (M1~M4는 릿지 회귀)
- 인근 현: 현 대표 좌표 사이 거리가 가장 가까운 세 현
- 지표: 로그 MAE(주 지표), 원래 단위 MAE와 RMSE, 규모 보정 MAE. 신뢰구간은 현 단위 부트스트랩 2,000회
- 외부 자료는 쓰지 않았다(대회 규정). 문헌은 배경과 해석에만 인용했다

추가 분석에서 임의로 정한 값

- 그래디언트 부스팅: 학습률 0.05, 300회 반복, 조기 종료 없음. 주제를 정할 때 시험 삼아 쓰던 값 그대로이고 결과를 보고 바꾸지 않았다
- 유행 시작 주: 5~52주 실제 최댓값의 25% 이상인 주가 2주 이어지는 첫 주 (10%, 50%로도 확인)
- 주 묶음 부트스트랩: 예측 시점을 8주씩 묶어서 다시 뽑음 (현 단위 구간과 비교용)
- 코로나 유행기: 전국 합계가 2013~2019년 최솟값보다 낮았던 2020년 17~40주. 2020년 10주(전국 휴교 요청 직후)부터 그해 말까지, 2021년 26주까지로 넓힌 것도 확인
- 기준 모델 강화: 계절 입력(sin, cos)을 네 모델에서 제외. 이때의 무작위 3현 대조는 50번
- 부스팅 계산 잡음: 인근 입력에 1e-12 크기의 정규 잡음을 더해 10번 반복
- 모의실험: 감염 기간 1주, 면역 평균 52주, R0 3, 계절 진폭 25%, 2020년 10주부터 1년간 전파율 50%(30%, 70%도 확인), 현 사이 연결 비중 0.5%, 외부 유입 1e-8. 자료에 맞춘 값이 아니고, 연결 비중과 외부 유입은 몇 번 돌려 본 뒤에 잡았다
